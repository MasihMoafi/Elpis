# Love Spot agents · 18 October 2026

For Masih: put a character on the board, give it a task, draw an arrow to another character, run. Click a character to see its instructions, model, provider, tools, chat and answer. Six presets remove configuration from the first use; `@agent [role] task` in a note is the keyboard entry.

[ACP v1](https://agentclientprotocol.com/protocol/v1/overview) is JSON-RPC: initialize/capabilities, sessions, prompts, streaming updates, tools, permission requests and cancellation. [Transports](https://agentclientprotocol.com/protocol/v1/transports) describe local stdio; network access needs an explicit transport and authentication boundary. ACP does not schedule a graph or define answer handoffs. [SDKs](https://agentclientprotocol.com/libraries/typescript) cover TypeScript, Rust, Python, Kotlin and Java. The official [client catalog](https://agentclientprotocol.com/overview/clients) includes Zed, JetBrains, Neovim integrations, Obsidian's Agent Client and desktop/web clients such as AionUi and ACP UI.

[fx](https://github.com/vercel-labs/fx) is Vercel's small embeddable Zig coding agent: `fx acp` exposes ACP; libfx embeds its core. [Cloudroom](https://github.com/davidondrej/cloudroom-core) is David Ondrej's self-hostable Rust agent runtime, with a [desktop app](https://www.cloudroom.dev/docs/get-started) for local/cloud threads using the user's agent logins. Its [adapter documentation](https://github.com/davidondrej/cloudroom-core/blob/main/docs/harnesses.md) shows OpenCode over ACP alongside native drivers such as Claude's stream JSON. These are references, not dependencies or newly supported remote endpoints.

Design: native Excalidraw rectangles contain character metadata in `customData`; generated local SVG portraits and bound text make the cards portable drawings. Native bound arrows define directed edges. A bridge route reads the saved scene, validates the complete graph before starting, then runs the selected character's connected component in topological order. Each character runs as its own ACP agent process, and agents reach each other only over ACP (18 October): the bridge is the ACP client of every card, and a card's final answer reaches the cards its arrows point to through their `session/prompt`. Only completed final answers feed successors (the last agent message of the turn, never Elpis commentary). Multiple incoming answers carry source names. Results, ACP session IDs and, for Elpis agents, the chat (thread) ID are saved back on each card; errors halt dependent work. The browser can navigate away while the server finishes.

ACP transport: `bridge/acp-nodes.mjs` `runAcpNode(spec, { task, inputs }, options)` starts one ACP agent over stdio (initialize, `session/new` with the card's instructions in `_meta.systemPrompt.append`, `session/set_config_option` for the model, one `session/prompt`), streams its `session/update`s, routes `session/request_permission` to the card, and cancels with `session/cancel` on timeout. A card maps to an agent by its model and provider: the Elpis ACP agent (`tools/elpis-claude/elpis-acp-agent.mjs`, also `elpis acp --model M`) for engine models, each session an Elpis thread on a private `elpis app-server`; claude-agent-acp for `claude/…`; agy-acp.mjs for `agy/…`; or a command configured for the provider in `$ELPIS_HOME/acp-agents.json`, e.g. `{"fx": {"command": "fx", "args": ["acp"]}}`. The Workflows bridge runtime calls the same `runAcpNode` for its stage transitions. Presets default to gpt-6-luna/OpenAI and can be edited. Remote (non-stdio) ACP connections remain future work.

Trade-offs: sequential execution simplifies dependency and failure handling; independent branches wait. Fresh chats make each run reproducible and visible; repeated runs create new history. Local SVG generation gives six distinct portraits without a download or model call. An agent's permission request waits on its card; the panel shows the agent's options and the answer goes back over ACP (`POST /api/love-spot/agents/permission`). Board snapshots define a run; edits during a run apply to the next run.
