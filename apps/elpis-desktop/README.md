# Elpis desktop

A Next.js/shadcn app with an Electron window, connected to the existing private Elpis runtime socket. Closing the app leaves conversations running. Browser and desktop share one interface and native thread storage.

The desktop's Browser button opens websites beside the workspace, with tabs, address entry, history, reload/stop and reply links. Hiding the pane or reloading the interface keeps tabs; closing the app ends the tab set. Websites use a separate session without Elpis runtime access. The composer microphone reuses the configured WhisperType MCP server (local, OpenRouter or Codex sign-in), displays its route, and inserts text without sending. Recording/transcription can be cancelled; changing chats cancels it. Two-minute/8 MB limits apply. Run `npm run test:desktop` for browser and dictation checks.

From this directory: `npm ci`, `npm run build`, then `npm run desktop` (or `desktop/launch.sh`). The desktop starts or reuses the installed Elpis runtime; no terminal window is required. `ELPIS_ENGINE_BIN` selects another installed engine with its bundled provider bridge. For a browser, start Elpis, run `npm run web`, and open its private URL. `ELPIS_APP_BRIDGE_SOCKET` selects a specific existing Unix socket and disables automatic runtime startup. `desktop/launch.sh --desktop-entry` prints a `.desktop` launcher for this checkout (`StartupWMClass=elpis-desktop`, the Elpis website's mark as icon); the script installs nothing.

Conversations and agents are named by their task: the recorded title, else the first request, else the task a parent gave a spawned agent; nicknames are secondary. Your chats rejoin natively, so they stream, can be stopped, and their approvals appear here. Headless (`exec`) and subagent runs stay out of ordinary chat lists, search and unread counts; the folded “Agent runs (n)” group shows the loaded runs and their parent titles. Opening a run shows its history read-only. Once it finishes, “Continue here” forks its saved history into a normal chat with the same model, keeping the original run and parent ownership intact. “Show agents” opens that group, which also holds child pagination. Conversations and agents can be deleted (with confirmation); chats continued from a deleted agent are deleted with it. The Agents page shows each agent's state and current action live; New agent starts a named root chat with its own model, folder and instructions. A chat's model and reasoning effort can change for its next turn; switching provider mid-chat is limited to subscription models (the engine has no per-turn provider). Providers are labelled from the model prefix (`claude/` Claude subscription, `agy/` Gemini/Antigravity).

Agents keeps discovering descendants while its page is visible, even with collapsed sidebar parents. Native waiting-on-approval/input flags appear as Needs input. Load more controls expose older conversations and child pages, which remain loaded through refresh. Filters retain parent context; opening the page does not start a task.

Settings has fourteen pages, modelled on the ChatGPT app: General, Notifications, Appearance, Keyboard shortcuts, Voice, Personalization, Models & accounts, MCP servers, Usage & limits, Git, Worktrees, Hooks, Configuration and Archived chats. General and Notifications are saved on this device (`lib/preferences.ts`; the desktop reads Confirm before closing natively); everything else goes through the native versioned config writer with stale-write protection. Models & accounts shows each provider's own sign-in (OpenAI/ChatGPT, Claude, Gemini), and edits OpenRouter, local and custom API endpoints using the native Responses protocol. API keys can be replaced or cleared, and are never returned to the renderer. Explicit API providers use their own credentials and model IDs. Managed or command-based authentication remains read-only. MCP servers lists the configured servers with credential presence only, and adds, removes or enables them; RAG appears there with its provider, model and key settings, and `/rag` instructions use the same canonical prompt across providers. Voice sets WhisperType's OpenRouter model and the fallback engine; the composer's microphone transcribes with the chat's own provider (ChatGPT sign-in for ChatGPT, the Voice model for OpenRouter, the fallback for providers with no transcription Elpis can reach). Usage & limits shows each account's limits and the selected chat's context. Personalization holds custom instructions (`developer_instructions`) and memories; Configuration holds approval, sandbox, web search, output and reasoning-summary defaults, the background model and Smart Prune. Git edits `project_root_markers`, Worktrees `desktop.git-worktree-root`, and Hooks enables or trusts discovered hooks in `hooks.state`.

Workflows start empty. Add tasks, connect their dependency ports or remove a connection with its delete control, arrange and zoom the canvas, set concurrency and timeouts, validate, save locally or export. Explicit Run calls the native persisted scheduler; Stop targets the acknowledged workflow turn. Tasks can inherit the root's route or select a configured native API provider and model. Each task uses that provider's own credentials, and its effective route is recorded with its result. Explicit task routes require the updated runtime's `workGraph/runWithProviders` method; an older runtime rejects the request. Claude and Gemini subscription routes are rejected before workers start, because the scheduler cannot yet execute through those adapters. Drafts never launch workers.

Provider edits, including clearing a stored key, apply to new conversations and agents. Existing conversations retain their original provider configuration and credentials; clearing a stored key does not revoke those credentials at the provider. Start a new root conversation to use changed provider settings in a workflow, too: its workers use the provider configuration captured by that root.

Leaving a subscription model for a native model requires the current subscription turn to finish. A busy switch is rejected and preserves the current selection. Changing an arbitrary API provider requires a new conversation.

Provider history is paged within the desktop connection's size limit. A single history item larger than the page budget produces an explicit error; its saved content is preserved.

The app reconnects after a runtime disconnect, restores subscriptions and refreshes state while preserving the composer draft. A write whose result is unknown is never automatically replayed; inspect the conversation before resending. Closing the desktop leaves the shared runtime and its conversations intact.

The desktop restores the selected chat, exact unsent drafts, named projects and appearance after closing and reopening, independently of its loopback port. Projects use existing folders through the native chooser or an absolute path; switching projects sets the folder for new work and filters chats by their recorded folder. Existing chats retain their own folder. Unavailable/duplicate folders and storage failures are reported. The optional web version retains per-window draft recovery. Failed sends retain their text; retrying a failed first agent message uses the already-created conversation. Run `npm run test:drafts` and `npm run test:desktop` for focused checks; `tests/project-journey.runtime.mjs` checks the actual desktop and installed runtime with isolated local inference.

Checks: `npm run typecheck`, `npm run test:bridge`, `npm run test:ui`, `node tests/runtime.mjs /absolute/elpis-next [--pruner]`, and the acceptance run `node tests/app-fix-2.runtime.mjs /absolute/elpis-next [--shots DIR]`, which drives the real runtime with a local inference fixture. Browser checks need Playwright/Chromium (`ELPIS_PLAYWRIGHT_PACKAGE`, `ELPIS_CHROMIUM`). With `NODE_USE_ENV_PROXY=1` in the shell, run the bridge tests with it unset: Node then proxies the raw-Host loopback check.

Current limits: distribution packaging and subscription-provider workflow execution are unfinished. Local checks do not establish user acceptance, coding quality improvements or production readiness.

Ctrl+K → **Improve Elpis…**, or right-click → **Change this…**, starts a Luna chat with a build-mapped source component and a captured region. It edits a fresh `improve/*` worktree. Build and test exit codes accompany the committed diff; **Try it** opens the candidate desktop build with a disposable profile and the installed engine. **Keep** writes a ready note for the coordinator; it does not merge or install. Run from a source checkout, or set `ELPIS_SOURCE_REPO` to the Elpis checkout (packaged apps need this setting). Existing dependencies are linked without installing packages. Evidence and ready notes live in `~/.cache/elpis-improve`, overridable with `ELPIS_IMPROVE_HOME`. Focused checks: `node --test bridge/improve.test.mjs bridge/source-map.test.mjs desktop/improve.test.cjs`, `tests/improve.test.cjs`, and `tests/improve-capture.runtime.mjs`; `tests/improve-live.runtime.mjs <installed-engine>` runs the isolated subscription check.
